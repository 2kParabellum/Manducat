# Архитектура Manducat

## Принципы

1. **Правила — отдельно от всего.** Пакет `@manducat/core` — чистые функции без браузера, сети и случайности «из воздуха». Один и тот же код работает в браузере, на сервере, в тестах и в симуляциях ИИ.
2. **Одна правда, много «видов».** Настоящее состояние партии (`GameState`) знает всё: закрытые карты, все мины. Игрок видит только `PlayerView`, где закрытые карты без сути, а чужие мины скрыты. Интерфейс рисует **только вид**, ИИ думает **только по виду**. Поэтому онлайн-режим не потребует переделки интерфейса, а читерство через инструменты разработчика невозможно.
3. **Интерфейс общается с партией только через сессию** (`GameSession`): отправляет ходы, получает обновления. Сейчас есть локальная сессия, позже рядом появится сетевая с тем же интерфейсом.
4. **Всё сериализуемо.** Состояние, ходы (`Action`) и события (`GameEvent`) — простые JSON-данные: их можно отправить по сети, сохранить и проиграть заново.
5. **Детерминизм.** Раскладка зависит только от семени (`seed`), поэтому партии можно повторять, отлаживать и использовать как фиксированные уровни.

## Структура

```
packages/
  core/      правила игры
    types.ts         типы: карты, ходы, события, состояние, настройки правил
    board.ts         геометрия поля 6×6
    pieces.ts        сила, очки, «кто кого бьёт»
    abilities.ts     персонажи и способности (реестр)
    rules.ts         допустимые ходы, проверка хода
    engine.ts        создание партии, применение хода, конец партии
    view.ts          вид игрока и фильтрация событий
    rules-config.ts  числа правил по умолчанию (39 очков, перезарядка 15 и т. д.)
  ai/        искусственный интеллект
    knowledge.ts     что бот знает сверх вида: подсмотренные карты, вероятные мины
    belief.ts        позиция «глазами бота» и быстрые симуляции
    evaluate.ts      оценка позиции и её веса
    search.ts        перебор (expectimax)
    bot.ts           бот и уровни сложности
    arena.ts         матчи бот против бота
apps/
  client/    веб-клиент (Vite)
    src/session/     сессии: types.ts (интерфейс), local.ts (ИИ и двое за экраном)
    src/ui/          экраны: партия, настройка, окна
    src/content/     тексты: персонажи, сообщения о событиях
    src/meta/        настройки игрока (тут же появятся профиль, прогресс, покупки)
tools/
  sim.ts     турнир ботов для балансировки
```

Зависимости строго в одну сторону: `client → ai → core`, `client → core`. Ядро не знает про ИИ и интерфейс, ИИ не знает про интерфейс. В пакетах `core` и `ai` не подключены типы браузера, поэтому случайное обращение к `window` или `document` не скомпилируется.

## Поток данных

```
 Человек ──клик──► GameScreen ──submit(Action)──► GameSession
                       ▲                              │
                       │                     isLegalAction → applyAction
                       │                              │  (GameState — правда)
                       │                              ▼
                       └──── SessionUpdate ◄── getPlayerView + redactEvents
                         (вид + события для этого зрителя)

 Бот: observe(вид, события) → chooseAction(вид) → тот же submit
```

`GameScreen` складывает обновления в очередь и проигрывает их по одному: подсветка хода соперника → новый вид → анимации событий → следующий ход.

## Ключевые понятия

| Понятие | Где | Что это |
|---|---|---|
| `GameState` | core | вся правда о партии |
| `PlayerView` | core | что знает конкретный игрок |
| `Action` | core | ход: открыть, сдвинуть, съесть, выложить M, способность |
| `GameEvent` | core | что произошло за ход (для анимаций, лога, знаний ИИ) |
| `RulesConfig` | core | числа правил (уровни кампании смогут их менять) |
| `GameSession` | client | канал «интерфейс ↔ партия» |
| `Bot` | ai | бот, который помнит увиденное и выбирает ход |

## Как добавить персонажа

1. `core/src/types.ts`: добавить id в `CharacterId` (и в `AbilityId`, если способность новая).
2. `core/src/abilities.ts`: описать способность (`targets` и `apply`) и запись в `CHARACTERS`.
3. `client/src/content/characters.ts`: имя, иконка, описание, подсказка.
4. Если у способности особая ценность для ИИ (как у разведки или мин) — научить `ai/src/evaluate.ts` и `ai/src/search.ts`.
5. Тесты в `core/test/rules.test.ts`, баланс через `npm run sim`.

## Как сюда лягут будущие функции

**Мультиплеер.** Появится `apps/server`: Node.js с WebSocket (план — Colyseus: комнаты, переподключение, подбор). Сервер хранит `GameState`, принимает `Action`, проверяет `isLegalAction`, применяет `applyAction` и рассылает каждому `getPlayerView` + `redactEvents`. В клиенте появится `OnlineSession`, реализующая тот же `GameSession`. `GameScreen` уже умеет показывать ходы соперника, которые приходят извне.

**Кастомные лобби и поиск.** Это слой сервера над комнатами: код комнаты или ссылка для своих, очередь подбора по рейтингу для поиска. Ядро не меняется.

**Рейтинг.** Эло или Glicko считается на сервере по `GameResult`. Клиенту рейтинг приходит как данные профиля.

**Кампания.** Уровень — это данные: `GameSetup` (свои `rules`, готовая раскладка `layout`, персонаж и сложность бота) плюс условия победы. Прогресс и открытые персонажи хранятся в профиле (`client/src/meta`, позже на сервере). Детерминизм ядра позволяет делать уровни с фиксированной раскладкой.

**Платный контент.** Набор доступного (персонажи, косметика) — «права» в профиле. Для онлайна их проверяет сервер при создании партии: недоступного персонажа выбрать нельзя. В приложениях покупки идут через App Store и Google Play.

**Ачивки.** Слушатели событий (`GameEvent`) и результата партии: «съесть 8 единицей», «победить, взорвав 3 мины» и т. п. Локально их можно считать в клиенте, для онлайна — на сервере, чтобы нельзя было накрутить.

**Более сильный ИИ.**
- Расчёт хода — в Web Worker, чтобы интерфейс не подвисал.
- Перебор информационных множеств (ISMCTS) вместо фиксированной глубины.
- Подбор весов оценки самоигрой через `tools/sim.ts`.

Интерфейс `Bot` при этом не меняется.

**Мобильное приложение.** Клиент собирается в обычные статические файлы с относительными путями. Дальше его можно сделать PWA или завернуть в Capacitor для App Store и Google Play.

## Команды

```
npm install        установить зависимости
npm run dev        клиент в режиме разработки
npm run build      сборка клиента в apps/client/dist
npm test           тесты (правила, вид игрока, боты)
npm run typecheck  проверка типов всех пакетов
npm run sim -- --games 20 --a hard:miner --b normal:jack    турнир ботов
```
